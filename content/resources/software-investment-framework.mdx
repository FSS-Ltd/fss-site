## How should we compare software investments?

Compare the same operational outcome across keeping the current process, configuring an existing product, integrating tools and commissioning bespoke work. Record evidence, assumptions, one-off costs and recurring responsibilities for each option. The existing framework PDF supports the decision; these examples explain how to apply it.

## What belongs in the comparison?

Start with the problem, its owner, the essential tasks and the consequence of doing nothing. Record available evidence beside each expected benefit. Separate measurable observations from assumptions and decide what would disprove the business case.

Include discovery, configuration or build work, migration, training and launch. Then record subscriptions, hosting, maintenance, support, staff administration and the cost of leaving. The [software cost guide](/guides/custom-software-cost-uk) explains scope drivers without treating an illustrative budget as a quotation.

## How might a charity use the framework?

Consider an illustrative programme team copying referral status into a funder report. Compare improving the existing export, joining supported data sources and building a reporting workflow. Test whether source definitions agree before promising faster reporting.

Record staff time as potential capacity released. Do not count the same hours as both salary savings and additional delivery capacity. Use the [Manual Process Audit](/resources/manual-process-audit-fss) to collect baseline evidence.

## How might a church use it?

An illustrative church reviewing registration and volunteer coordination could compare a configured church management product, a targeted portal and a bespoke release. Include occasional users, access removal when volunteers leave and a fallback process during downtime.

Use the [church software comparison](/blog/church-management-software-vs-bespoke) to structure product trials. Ask users to complete representative tasks and record which essential needs remain unmet.

## What should trustees or budget holders approve?

Present a preferred option with reasons, material uncertainties, a named owner and a first decision boundary. A discovery phase can be approved to test a risky assumption before a wider commitment. State what evidence would cause you to pause or choose another option.

Scoring helps organise a discussion; it should not hide a serious dependency behind an average score. Do not present estimated returns as guaranteed outcomes.
