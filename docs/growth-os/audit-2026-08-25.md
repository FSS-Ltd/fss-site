# Growth OS implementation and release audit

**Date:** 25 August 2026  
**Reviewer:** Codex, Technical Agent  
**Scope:** Growth OS plans 01 through 07, the design specification, FSS Agent
Operating System v2, CI, and the Vercel preview configuration  
**Release verdict:** **Not ready for production or unattended automation**

## Executive position

The Growth OS application is substantially implemented. Its domain rules,
private PostgreSQL model, signed ingestion contract, Gmail and Resend
abstractions, founder-only dashboard, commercial lifecycle, and release
runbooks have strong automated coverage.

The release is not complete. The current Vercel environment contains invalid
or blank database, authentication, Google, encryption, and Resend values. The
reviewed preview therefore returns `500` for every Growth OS protected, cron,
webhook, and agent-ingestion route. The manual provider, visual, cutover, and
rollback evidence required by Plan 07 is also incomplete.

Production promotion and the weekday research task must remain disabled until
the preview gate passes and Jean-Fidele gives explicit cutover approval.

## Findings

### Release blockers

1. **The Vercel runtime configuration is invalid.** Preview runtime logs report
   invalid `DATABASE_URL` and `DIRECT_DATABASE_URL`; weak or blank
   `AUTH_SECRET` and `TOKEN_ENCRYPTION_KEY`; and blank Google Auth and Resend
   values. Public `/` and `/sitemap.xml` return `200`, while `/growth`,
   `/api/growth/health`, every cron route, signed research ingestion, and the
   Resend webhook return `500`.

2. **The intended FSS Supabase project is not connected in the available
   project list.** Database migrations passed against isolated PostgreSQL 17,
   but no claim is made that the target hosted database has those migrations.

3. **Live provider verification is absent.** Dedicated Gmail OAuth values,
   the exact callback, Resend test configuration and webhook secret, and the
   Vercel Blob token remain unverified or missing.

4. **The production cutover gate has not been authorised.** The Vercel project
   has no reviewed live canonical cutover. Merging to `main` also retains the
   existing Netlify production workflow, so a merge is a production-affecting
   action and requires explicit approval.

5. **The weekday company-research task cannot run safely yet.** The task exists
   on the required weekday 06:00 Europe/London schedule, but it is paused. It
   still needs an approved public ingestion URL and a least-privilege local
   copy of the matching HMAC secret. It must not receive the complete Vercel
   production environment.

### Defects corrected in PR #110

1. The previous GitHub workflow could pass while all 46 Growth OS PostgreSQL
   integration tests were skipped because no database URL existed in CI.
   CI now provisions PostgreSQL 17, applies all migrations, validates that the
   database URL exists, and runs the database suite serially.

2. CI and Vercel used different Node major versions. The repository and CI now
   target Node 24, while the package engine prevents unreviewed Node 25
   adoption.

3. The default lint command traversed Claude worktrees and could report errors
   outside the reviewed source tree. The generated worktree path is now
   excluded.

4. No automated FSS coverage gate existed. The combined unit and PostgreSQL
   integration command now enforces at least 80% line, branch, and function
   coverage for the Growth OS source surface.

5. Running the previously skipped database tests exposed invalid shared test
   cleanup and newsletter approval fixtures. Those fixtures now respect the
   sequence foreign key and seed explicit newsletter consent.

## Required release sequence

1. Merge PR #110 only with explicit production-impact approval.
2. Connect the intended FSS Supabase project and set valid Preview-scoped
   database URLs.
3. Set valid Preview values for Auth.js, dedicated Gmail OAuth, token
   encryption, Resend, webhook verification, and Blob.
4. Redeploy the reviewed commit and complete every item in
   `docs/runbooks/growth-os-preview-checklist.md`, including founder visual
   sign-off.
5. Obtain explicit cutover approval, promote with
   `GROWTH_OS_AUTOMATIONS_ENABLED=false`, and run the production smoke checks.
6. Place only the agent ingestion URL and matching HMAC secret in the scheduled
   task's secret boundary, then activate the weekday task.
7. Enable provider automations separately through the documented two-gate
   rollout. Keep Netlify available for the rollback window.

No production deployment, database migration, provider send, DNS change, or
automation activation was performed during this audit.
