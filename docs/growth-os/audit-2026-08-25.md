# Growth OS implementation and release audit

**Date:** 25 August 2026  
**Reviewer:** Codex, Technical Agent  
**Scope:** Growth OS plans 01 through 07, the design specification, FSS Agent
Operating System v2, CI, and the Vercel preview configuration  
**Release verdict:** **Not ready for production or unattended automation**

## Executive position

The Growth OS application is substantially implemented. Its domain rules,
private PostgreSQL model, signed ingestion contract, Gmail and Resend
abstractions, founder-only dashboard, commercial lifecycle, and release
runbooks have strong automated coverage.

The release is not complete. The intended Supabase database and the
least-privileged production runtime credential are now configured, and the
core runtime secrets and Blob storage are isolated by environment. The current
production deployment predates those changes and still cannot boot because
the required Google Auth client is blank. Dedicated Gmail OAuth and the Resend
webhook signing secret also remain unverified. The manual provider, visual,
cutover, and rollback evidence required by Plan 07 is incomplete.

Production promotion and the weekday research task must remain disabled until
the runtime and provider gates pass. The canonical domain is now on Vercel, and
Jean-Fidele's explicit cutover approval is recorded below.

## Findings

### Release blockers

1. **The deployed Vercel runtime still cannot boot.** The reviewed production
   deployment was built before the database and secret remediation and reports
   invalid database and blank Google Auth values. The project configuration now
   has a valid Production-only `DATABASE_URL` plus independent Production and
   Preview core secrets, but Google Auth must be configured before redeployment.

2. **Preview has no isolated database.** Production is connected to the
   intended hosted Supabase project with a least-privileged runtime role.
   Preview intentionally has no `DATABASE_URL` rather than receiving Production
   data access; it needs a separate branch or database before database-backed
   Preview checks can pass.

3. **Live provider verification is incomplete.** Google Auth and dedicated
   Gmail OAuth values, the exact Gmail callback, and the Resend webhook secret
   remain unverified or missing. Separate Production and Preview Vercel Blob
   stores are now attached in Paris.

4. **The production cutover gate is partially complete.** Jean-Fidele has
   authorised the production-affecting work, and the apex plus `www` now return
   Vercel response headers. The provider and runtime checks must still pass
   before Netlify is retired.

5. **The weekday company-research task cannot run safely yet.** The task exists
   on the required weekday 06:00 Europe/London schedule and now has the approved
   production base URL plus a least-privilege local Keychain copy of the
   matching HMAC secret. It remains paused until the live endpoint boots and a
   controlled run passes persistence and replay checks.

### Defects corrected in PR #110

1. The previous GitHub workflow could pass while all 46 Growth OS PostgreSQL
   integration tests were skipped because no database URL existed in CI.
   CI now provisions PostgreSQL 17, applies all migrations, validates that the
   database URL exists, and runs the database suite serially.

2. CI and Vercel used different Node major versions. The repository and CI now
   target Node 24, while the package engine prevents unreviewed Node 25
   adoption.

3. The default lint command traversed Claude worktrees and could report errors
   outside the reviewed source tree. The generated worktree path is now
   excluded.

4. No automated FSS coverage gate existed. The combined unit and PostgreSQL
   integration command now enforces at least 80% line, branch, and function
   coverage for the Growth OS source surface.

5. Running the previously skipped database tests exposed invalid shared test
   cleanup and newsletter approval fixtures. Those fixtures now respect the
   sequence foreign key and seed explicit newsletter consent.
